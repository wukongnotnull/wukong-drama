# 版本怎么递增

**先说明建议版本并征得用户明确允许，再修改版本号。** 功能、文档修改或开发构建不自动升版，spec 通过也不代表允许升版。

插件与引擎使用同一个版本号，从 **0.1.0** 起算。已发布版本和安装包见 [GitHub Release](https://github.com/wukongnotnull/wukong-drama/releases)。

| 改了什么 | 下一个版本示例 |
| --- | --- |
| 修问题、改文案，现有用法不变 | 0.1.1 |
| 增加功能 | 0.2.0 |
| 0.x 阶段改变旧用法 | 0.2.0，并提供迁移说明 |
| 功能和接口稳定，准备长期兼容 | 1.0.0 |

每次从当前版本递增，不重复使用已发布的编号。开发验证包沿用当前版本并标记 development，不当作正式包分发。

升版以 `plugin/plugin.json` 为准，同步宿主清单、marketplace、引擎和锁文件，再运行 `node tools/build-agent-docs.mjs`。画风的最低引擎版本按实际需要维护，不必随每次修复升高。

旧安装版本高于新包时，先备份作品、按原方式卸载，再安装；不要绕过降级或同版本覆盖检查。

发布前运行 `npm test`、`npm run lint`，从干净提交构建并核对两种包的版本和来源。只有实际发布时才创建对应的 `v版本号` 标签。

发版时同步 `tools/build-agent-docs.mjs` 的 `publishedVersion` 并重新生成安装说明，避免把未发布的源码版本当成下载版本。

## 升级到 0.2.0

默认使用模型原生声音，删除固定人声来源和声轨审听，改为14道工序、11个审片节点。声音要求随剧本／分镜确认，实际效果随小样审查；独立配音与后期调音按需保留。

旧流程9–16道对应新7–14道。原声音批准只留历史，原字段保存在 legacy；交付账本不改写。旧待存档批准无法核实时先停下复核，使用当前编号和新的 approval-id 时归档旧记录。保留素材、任务和草稿，不自动重新付费生成。旧版不支持流程7，升级前请备份完整作品目录。已发布0.1.0安装包不受源码修改影响。

新分镜增加首帧、过渡、尾帧提示词，直接用于图片和视频生成；尾帧目前仅为文字目标。旧素材和已提交任务可继续复用，新生成前才补齐相关三栏并审查。新表以分镜提示词为准，旧 JSON 中重复的 image_prompt／video_prompt 需同步或移除，不补造历史批准。
