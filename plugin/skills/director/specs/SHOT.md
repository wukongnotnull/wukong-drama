# 镜头文件规范（shots/sNN.json）

每镜一个 JSON 文件，图片描述负责构图，视频描述负责动作。第 9 道建立风格帧，第 10 道生成视频。`wkd init` 为所有风格生成模型镜头，不要求编写画面 JS 或 React。

```json
{
  "image_prompt": "水墨远景，右下角小舟与远山形成层次，宣纸暖白底，主体旁留白，底部留字幕安全区",
  "video_prompt": "小舟缓缓向左，船型和人物衣着不变，雾气轻动，固定机位，不加文字，不切镜，结尾停留",
  "settings": [{"kind":"prop","id":"boat","version":"v1"}],
  "references": ["assets/references/boat.png"],
  "revision": "v1"
}
```

| 字段 | 含义 |
|---|---|
| `image_prompt` | 图片构图、主体、环境、风格与不应出现的内容 |
| `video_prompt` | 起始状态、主要动作、运镜、结束状态、稳定约束 |
| `settings` | 本片清单中的 `{kind,id,version}` 数组；自动补入已批准文字与参考快照，无对象写 `[]` |
| `references` | 本地参考图片路径数组，相对影片目录；角色、服装、道具和环境保持一致 |
| `image` | 可选，导入已经生成并核对过的本地图像，相对影片目录 |
| `video` | 可选，导入已经生成并核对过的本地视频，相对影片目录 |
| `revision` | 可选生成修订号；只有明确需要重新生成时才更改 |

路径指向实际存在的本地文件。密钥不进入 JSON；模型配置在 `film.json` 的 `generation` 或环境变量。格式以引擎校验为准，不在 JSON 写注释或未声明的字段。

## 角色与镜间连续性

三类设定在项目 `characters.json`、`props.json`、`scenes.json` 中维护，按 [SETTINGS.md](SETTINGS.md) 在第 5 道确认。镜头 settings 精确引用本片选中的版本，自动使用批准时的参考快照；额外 references 的路径仍不得用 `../` 逃出影片目录。

项目角色档案记录：年龄范围、脸型、发型、服装、配饰、性格动作和禁止变化项。跨镜复用同一组已批准参考图，在提示词里沿用稳定描述。技术风格写在提示词中，分镜表继续面向观众描述画面。

连续镜头先核对前镜末尾与后镜开头的人物、道具和环境。参考图能提高一致性，不能保证模型逐帧不变。生成后实际看手部、脸、服装、道具、镜间方向和动作连续性；失败只返修受影响镜头。

## 生成与恢复

视频数量、剪辑／源片时长、逐镜与整片路线、每批开始窗口和持续进度统一按 [视频批次规范](VIDEO.md)。`generation-approve --kind video` 必须携带用户看到的计划 `--signature`；变化后的计划重新展示并明确确认开始。

- `wkd still` / `animatic` 生成或复用分镜图；`render` / `preview` / `final` 生成或复用镜头视频后做 ffmpeg 后期。
- 模型、提示词、参考图内容、关联设定版本、画幅和修订共同决定生成签名。未确认或变化的设定阻止相关镜头生成。小样与高清共用原始模型视频，不分别付费生成。
- `assets/generated/<画幅>/<镜号>/<签名>/` 保存源图片、源视频与任务记录。它们是工程素材，必须备份；清后期缓存不得删除它们。
- 轮询超时保留原任务，重跑原命令续查。失败或提交结果不明确时先核对记录；确需重拍才更改 `revision`，不得通过删除记录偷偷重发。
- `--force` / `--only` 的后期重算不等于用户要求付费重新生成。重新生成前核对现有用户授权和当前镜头修订。

## 声音、文字与时长

人声、配乐、音效沿用第 8 道定下的声轨。镜头目标时长来自 `film.json`，模型视频会统一尺寸、帧率与时间轴；对动作被截断、停留不足或节奏变化必须实际检查。默认使用独立声轨；用户明确选择原生声音时设置 `generation.video.generate_audio: true`，并实际审听产出的原生音乐/音效。

字幕由引擎制作。题字、标题、代码或数字若进入生成画面，需要逐字核对；精确内容优先导入已核对图像或由后期字幕表达。模型提示词不能保证文字出现的词级时间或人物口型。`cues`、`sync-points.json` 可用于剪辑与听看依据，不能据此声称模型已经准确执行；只有实测的画面与音频才是通过证据。

## 副版

副版覆盖文件如 `shots/s03.9x16.json`，使用同一镜号、时长、声轨与角色参考，重排主体及字幕安全区。可提供已裁切的本地副版 `image` / `video` 或分别生成副版；主版文件和素材不覆盖。变更主版内容必须回到终审，不能借改版绕过。
