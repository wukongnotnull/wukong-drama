# 镜头文件规范（shots/sNN.json）

每镜一个 JSON 文件。新生成以分镜三栏为准，自动整理图片与视频指令。第 7 道建立风格帧，第 8 道生成视频。`wkd init` 为所有风格生成模型镜头，不要求编写画面 JS 或 React。

```json
{
  "image_role": "first_frame",
  "initial_state": "小舟停在画面右侧，尚未向左移动",
  "source_start": 0,
  "settings": [{"kind":"prop","id":"boat","version":"v1"}],
  "references": ["assets/references/boat.png"],
  "revision": "v1"
}
```

| 字段 | 含义 |
|---|---|
| `first_frame_prompt` | 可省略；若填写，须与分镜“首帧提示词”一致，副版对应副版重排表 |
| `transition_prompt` | 可省略；若填写，须与主版分镜“过渡提示词”一致 |
| `last_frame_prompt` | 可省略；若填写，须与分镜“尾帧提示词”一致，副版对应副版重排表；仅文字目标 |
| `image_prompt` / `video_prompt` | 旧工程、定调和设定图片批次仍可读取；新分镜生成时不另行维护，与自动指令不一致会阻止新提交 |
| `settings` | 本片清单中的 `{kind,id,version}` 数组；自动补入已批准文字与参考快照，无对象写 `[]` |
| `references` | 本地参考图片路径数组，相对影片目录；角色、服装、道具和环境保持一致 |
| `image` | 可选，导入已经生成并核对过的本地图像，相对影片目录 |
| `video` | 可选，导入已经生成并核对过的本地视频，相对影片目录 |
| `image_role` | representative 构图代表帧／first_frame 动作首帧。新视频必须明确 first_frame，不能默默转换用途 |
| `initial_state` | 首帧中实际可见的动作初态；随图片一起审阅 |
| `source_start` | 可选非负秒数，默认0；从完整源视频这一位置剪入，画面和原声同步选段，长度取 shots[].duration。越界会阻止后期，不自动重生 |
| `revision` | 可选生成修订号；只有明确需要重新生成时才更改 |

路径指向实际存在的本地文件。密钥不进入 JSON；模型配置在 `film.json` 的 `generation` 或环境变量。格式以引擎校验为准，不在 JSON 写注释或未声明的字段。

图片实际指令＝分镜首帧提示词＋已确认设定；视频实际指令＝首帧＋过渡＋尾帧＋计划镜长＋声音＋稳定要求＋已确认设定。三栏详见 [STORYBOARD.md](STORYBOARD.md)。本轮只传一张首帧图片，尾帧不生成图片、不作为硬性末帧约束。

## 角色与镜间连续性

三类设定在项目 `characters.json`、`props.json`、`scenes.json` 中维护，按 [SETTINGS.md](SETTINGS.md) 在第 5 道确认。镜头 settings 精确引用本片选中的版本，自动使用批准时的参考快照；额外 references 的路径仍不得用 `../` 逃出影片目录。

项目角色档案记录：年龄范围、脸型、发型、服装、配饰、性格动作和禁止变化项。跨镜复用同一组已批准参考图，在提示词里沿用稳定描述。风格和稳定要求写入分镜三栏，用可见画面描述，不写内部代码。

连续镜头先核对前镜末尾与后镜开头的人物、道具和环境。参考图能提高一致性，不能保证模型逐帧不变。生成后实际看手部、脸、服装、道具、镜间方向和动作连续性；失败只返修受影响镜头。

## 生成与恢复

视频数量、剪辑／源片时长、逐镜与整片路线、每批开始窗口和持续进度统一按 [视频批次规范](VIDEO.md)。`generation-approve --kind video` 必须携带用户看到的计划 `--signature`；变化后的计划重新展示并明确确认开始。

- `wkd still` / `animatic` 生成或复用分镜图；`render` / `preview` / `final` 生成或复用镜头视频后做 ffmpeg 后期。
- 本地 source_start 不改变模型任务身份；剪辑调整复用原片，相关后期证据会失效。生成前 content-review 与 signoff 的 content-signature 按镜头绑定实际材料，已存任务续查／已有素材本地后期不需要补造旧批准。
- 模型、提示词、参考图内容、关联设定版本、画幅和修订共同决定生成签名。未确认或变化的设定阻止相关镜头生成。小样与高清共用原始模型视频，不分别付费生成。
- `assets/generated/<画幅>/<镜号>/<签名>/` 保存源图片、源视频与任务记录。它们是工程素材，必须备份；清后期缓存不得删除它们。
- 轮询超时保留原任务，重跑原命令续查。失败或提交结果不明确时先核对记录；确需重拍才更改 `revision`，不得通过删除记录偷偷重发。
- `--force` / `--only` 的后期重算不等于用户要求付费重新生成。重新生成前核对现有用户授权和当前镜头修订。

## 声音、文字与时长

声音方向遵循已签批剧本和分镜。镜头目标时长来自 `film.json`，模型视频会统一尺寸、帧率与时间轴；对动作被截断、停留不足或节奏变化必须实际检查。默认保留模型原生声音（`generation.video.generate_audio: true`，省略同样开启），在分镜的人声、音效和声音铺底栏写清要求，自动带入视频指令；实际产出后审听。选择独立后期或无声视频时显式设为 `false`，避免重复叠加相同内容。

独立人声可由引擎生成字幕；模型原生对白需核对后手工准备 SRT，已有字幕默认保留。题字、标题、代码或数字若进入生成画面，需要逐字核对；精确内容优先导入已核对图像或由后期字幕表达。模型提示词不能保证文字出现的词级时间或人物口型。`cues`、`sync-points.json` 可用于剪辑与听看依据，不能据此声称模型已经准确执行；只有实测的画面与音频才是通过证据。

## 副版

副版覆盖文件如 `shots/s03.9x16.json`，使用同一镜号、时长、声轨与角色参考，重排主体及字幕安全区；首尾构图写入分镜的该画幅“副版重排”表，动作与声音沿用主版。可提供已裁切的本地副版 `image` / `video` 或分别生成副版；主版文件和素材不覆盖。副版复用主版原生声音及其选段，不采用副版模型新声音；实际检查动作同步。变更主版内容必须回到终审，不能借改版绕过。
